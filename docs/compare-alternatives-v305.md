Compare now starts from the selected listing title/model rather than its discovery interest query. This prevents a discovery label such as Oatmeal from overriding a Light Orewood Brown source listing. Numbered sneaker model families are recognized independently of colour and style-code suffixes; other products use their title and existing identifier rules.

The existing exact-identity search, bounded pagination and shorter-query retry remain first. With fewer than four same-condition exact offers, a bounded additional request searches the same model without colour where a model can be established. If neither same-condition exact offers nor same-model alternatives are found, one named product-family request can supply Similar items. Fallback searches keep the exact pagination cursor; Load more continues that exact search. Previously retrieved candidates are retained so enabling an alternative tier can reuse already loaded offers.

Exact offers, other conditions, same-model alternatives and similar items have separate groups. Only same-condition exact offers enter Matches, Lowest and Typical price. Alternatives show their condition, and unknown shipping is labelled. Duplicate listing IDs/URLs, unavailable offers, incompatible currency, known accessories and counterfeit/parts terms remain filtered. Generic similarity is conservative lexical matching, not visual or catalogue verification; products without enough model/family evidence may still have no alternatives. Sizes and detailed condition differences remain visible in seller titles and labels rather than being normalized into identical variants.

Checks extend the existing identity and DOM suites: the reported Vomero flow, ASICS style codes across colours, Game Boy colours, exact-price isolation, wrong shoe models, insoles, currency, duplicate offers, next-family fallback and cancellation while a colour request is pending. Existing Compare return, pagination and reel handoff checks remain passing.
